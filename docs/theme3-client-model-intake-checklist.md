# Theme 3 Client Model Intake Checklist

Date: 2026-08-01

Scope: documentation only. This file does not add, modify, or wire any 3D models.

## Required Client Files

### 3D models

- Shank models
- Head models
- Side setting models
- Matching band models
- Any custom center stone models, if different from current preview models
- Any side stone/accent stone models, if separate from the ring/head model

### Textures and materials

- Metal material references
- HDR/environment maps, if custom
- Stone material references, if custom
- Normal/roughness/metalness maps, if used
- Any gemstone or colored diamond visual assets

### Preview and UI assets

- Option card preview images for shanks
- Option card preview images for heads
- Option card preview images for matching bands
- Stone shape images, if client-specific
- Colored diamond swatches/images, if client-specific
- Gemstone swatches/images, if client-specific
- Fallback images for unavailable/missing assets

- Model path
- Preview image path
- Price key or pricing rule ID

- Compatible center stone shapes
- Compatible heads
- Compatible shanks
- Compatible side settings
- Compatible matching bands
- Compatible metals
- Compatible purities/karats

- Head option to model file

- Side setting option to model file

## QA Checklist

### 3D model fit and alignment

- Model scale matches the current scene scale.
- Model origin/pivot is correct.
- Shank is centered in the scene.
- Head aligns correctly with the shank.
- Center stone fits the head.
- No visible shank/head gap.
- No visible stone/head clipping.
- Side stones fit correctly.
- Matching band fits beside the ring.
- Matching band does not intersect the shank.
- Bi-metal head accent applies only to intended head parts.

### Material and visual QA

- White gold, yellow gold, rose gold, and platinum materials look correct.
- Metal material reacts correctly to current lighting/environment.
- Gemstones and colored diamonds look visually distinct.
- Diamond transparency/refraction remains acceptable.
- Preview images match the 3D model options.
- Engraving remains legible where supported.

### Performance QA

- Initial model load time is acceptable.
- Switching shank/head/stone options remains smooth.
- Mobile performance remains usable.
- Model file sizes are optimized.
- No excessive memory usage after repeated option changes.
- Encrypted model loading still works if assets are bundled with the app.

### Browser/device QA

- Desktop Chrome
- Desktop Edge
- Mobile Chrome
- iOS Safari, if in project scope
- Common screen widths used for demos/client review

## Questions for Senior/Client Confirmation

- What model format should be provided: `.glb`, `.gltf`, `.obj`, or another format?
- Should production models be encrypted like the current `.enc` model workflow?
- Who will run or own the encryption process?
- What naming convention should model files follow?
- Should models be bundled statically in the app or managed by backend/config APIs later?
- Who validates visual fit and approves final 3D appearance?
- Who owns option compatibility rules: frontend, backend, client catalog, or Ring Builder?
- Are model assets store-specific or shared globally?
- Are preview images provided by the client or generated by us?
- Should every model have a SKU/product/variant mapping before it appears in the UI?
- Are any designs unavailable for certain metals, purities, or ring sizes?
- Are any designs unavailable for engraving?
- Does ring size require model scaling, separate models, or price-only behavior?
- Are matching bands sold independently, bundled, or both?
- What is the acceptable load-time and file-size budget for production?
